## Промежутки между секциями

Промежуток не равномерный, единого правила в макете нет:

- `0` — header → hero, cta → footer;
- `40` — после hero и после clients;
- `42` — после community;
- `48` — после case-study, achievements, guide, customers;
- `94.601` — после updates (перед cta).

Значения `42` и `94.601` выглядят как особенности макета, а не как
шкала. Требуют визуальной сверки с пользователем.

С точки зрения CSS разницы между `margin-bottom` предыдущей секции и
`padding-top` следующей нет — выбран `margin-bottom`.

## Контейнер

- Ширина секций — 1440 (на всю страницу).
- Поля контента — **144** слева и справа → ширина контента **1152**.
  Достигается контейнером `max-width: 1200px` + `padding-inline: 24px`
  (1200 − 48 = 1152), поля появляются центрированием бокса на экране 1440.
- Исключение — **header**: контент 1200 (поля 120), свой контейнер.

Это отвечает на вопрос, ширина ли текстового блока 1110 — нет:

- clients: текстовый фрейм `Clients` 1110 при контенте 1152 (отступы по 21);
- community: фрейм 1440, внутри заголовок отдельным боксом 542
  (отступы по 449), а Description на всю ширину 1440;
- updates: фрейм 1110 (отступы по 165), Description 628
  (отступы по 241 внутри фрейма).

То есть ширина текстового блока задаётся по секциям, общим правилом
не описывается. Для центрированного текста без переносов `text-align:
center` даёт тот же результат, что и бокс 1110.

## Вложенные секции

В header метаданные перечисляют 6 пунктов меню, а не 4:

`46, 57, 58, 60, 86, 31` px по ширине, промежуток 50 px, блок 588 px.

В HTML-скелет зашиты 4 пункта — расхождение с макетом, требует
решения (см. `sections/header.md`).
